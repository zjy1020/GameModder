# GameModder — 通用内存修改器

中文 GUI 的 Windows 进程内存数值修改工具，CE（Cheat Engine）式工作流，纯标准库实现（tkinter + ctypes），**无反作弊的单机/本地联机游戏**专用。

支持：数值扫描（精确值 / 范围值 / 多轮过滤 / 自动识别类型）、批量写入与锁定、**镜像透视与穿透写入**、**指针链回溯与静态路径复用**、游戏模板一键定位、手动任意地址读写、右键保存自定义模板。

> ⚠️ 仅限学习和研究用途。请勿用于带反作弊系统（EAC / BattlEye / Vanguard 等）的在线游戏，有封号风险。

### 方式一：直接运行 exe（推荐，无需装 Python）

下载 Release 里的 `GameModder.exe`，双击运行即可。

```bash
# Windows + Python 3.8+（需自带 tkinter）
python GameModder.py
```

## 使用教程

### 三步找到金币/声望的真实地址

以「扫金币 1000」为例：

1. **首次扫描**：输入游戏里显示的数值（如 `1000`），点 **① 首次扫描**。
   第一次命中成千上万是**正常的** —— 内存里很多地方都存着 1000。
2. **让数值变化**：回游戏花掉/赚到一点钱（比如变成 1800）。
3. **过滤收敛**：回来输入 `1800` 点 **等于新值**，或直接点 **已变化**。重复 ②③ 两三轮，候选会收敛到 1~3 个。
4. **写入验证**：选中地址 → 输入目标值 → **写入选中** → 回游戏看是否生效。

> **提示**：金币一般是 double 或 int64，血量/伤害可能是 float，声望这类整数计数通常是 int32。不确定就点 **自动识别类型**，四种类型自动扫一遍并推荐。
>
> **小数完全支持，位数不限**：输入侧按 double 解析，`422.72369384765625` 这种 17 位有效数字原样保留，`4.2` / `0.001` / `1.5K` 都行。显示侧用**最短可往返**表示 —— 看到什么值就照抄回去扫，一定命中：
> - `double` 类型显示全精度（`422.72369384765625`、`3.141592653589793`）
> - `float` 类型显示 7 位有效数字（`422.7237`），正好是 float32 精度上限，再多位数是噪声
>
> **输入精度不够时会自动容差重扫**：界面只显示 `422.72` 但你填进去精确扫描 0 命中 —— 工具会按你输入的**小数位数推算半格**（2 位小数 = ±0.005），自动用区间重扫一遍并提示。所以**按界面上看到的位数填就行，不用凑满精度**。「等于新值」过滤同样走容差，不会因为显示位数不够而误杀真值。
>
> **可能踩的坑**：`float` 类型上限约 `3.4e38`，超了会直接提示换 `double`/`int64`；整数类型（int32/int64）输入小数会**四舍五入**（`3.9` → `4`），不会静默截断。
>
> **输入支持大数缩写**：游戏界面显示 `2.3M` / `1B` / `500K` 这类缩写时，直接照抄输入即可（1K=千，1M=百万，1B=十亿，1T=万亿，大小写都行）。候选列表里的大数值也会自动附上缩写（如 `2288973.0  (2.3M)`），搜索框同样支持用缩写搜。
>
> **范围扫描**：游戏显示值常被四舍五入（如界面显示 `1M`，内存实际是 `1000002`），精确扫描会漏掉。此时输入区间如 `1M~1.01M` 或 `1000000-1010000` 扫一次，把落在区间内的值全部列出，再用「已变化 / 等于新值」收敛到真实地址。扫描页的首次扫描输入框同时支持两种写法：单个值（精确扫）或 `min~max`（区间扫）。

### 写入不生效？先点「锁定」

挂机类游戏的数值会**自动增长**，你写入的瞬间可能就被游戏逻辑覆盖了。

- 选中候选 → 填目标值 → 点 **锁定选中**，工具会每 0.3 秒持续写入，把值按死在目标值。
- 游戏内存里同一个数值常有**多个副本**（游戏逻辑用 / UI 显示用 / 存档缓存用），只写 1 个副本可能不生效。工具已内置「写后读回 + 延迟复查 + 自动补写」，日志会直接告诉你是哪一类问题。

### 写入还是不生效？去「指针/穿透」页 —— 你可能命中的是缓存镜像

有些游戏（尤其是用 **Fusion / Mirror / Photon 这类网络同步框架**的游戏）把状态值放在一块网络缓冲区里，
对象上的字段只是**每帧从缓冲区刷过来的镜像**。这时：

- 你写字段 → 立刻读回 → 一致（看起来成功了）
- 下一帧游戏执行 `CopyStateToBackingFields` → 你的值被覆盖回原样
- 回游戏一看，**数值没变**

**怎么识别**：写入后 150ms 再读一次，值变回去了 = 镜像实锤。工具已内置这个延迟复查（`写入选中/写入全部` 会自动做），日志里出现「已被游戏刷回 —— 这些是【镜像副本】」就是这种情况。

**怎么解决**，两个按钮：

| 按钮 | 干什么 |
|------|--------|
| **① 找镜像/别名（顺指针挖真值）** | 扫目标地址附近同一结构体内的所有指针字段，把每个指针**解引用**，看哪个指向的内存里躺着同一个值。命中的那个目标地址就是**真值副本**（缓存/权威值），写它才生效。 |
| **② 存活探测（真身 or 镜像）** | 对选中地址逐个写入一个「探针值」，等 150ms 再读。还保持探针值 = **真身**；被刷回 = **镜像**；写不进 = **失效**。一次就能把所有候选分类。 |

结果表里选中「镜像目标(真值)」行 → 填值 → 点 **写入选中行（含指针目标）**，写的就是穿透后的真值。

> 数值扫描页右键也有 **追查真值（转到 指针/穿透 页）**，选中候选地址一点就自动跳转并跑镜像透视。

### 地址每次重启都变？用「指针链」

Unity / 大多数引擎的对象地址**每次启动都会变**（ASLR + GC 压缩）。但「某个全局变量 → 偏移 → 偏移 → 字段」这条**指针路径**是不变的。

- 在 **指针/穿透** 页填上目标地址（或从扫描页 **← 取扫描页选中**），选好类型，设最大层级，点 **扫描指针链（回溯到模块）**。
- 工具会反向全内存搜索「谁指向这个地址」，逐层往上爬，直到爬到 **模块（.exe/.dll）内部** —— 那就是静态基准。
- 结果按「偏移越小越可能是真链」排序，标了 `#编号 静态链（重启可复用）` 的就是可用路径，形如：

  ```
  GameAssembly.dll+0x1A2B3C  →  [+0x18] + [+0x50] + [+0x8C]
  ```

- 选中 → **保存选中链**，下次启动游戏后点 **还原链(重解析)** 选它，地址自动算回来（`resolve_chain`：模块基址 + 偏移 → 逐层解引用加偏移）。

> 没爬出堆的会标 `堆链（仅本次运行有效）`——说明该对象没有静态引用（由 GC/容器直接持有），这种情况靠下面的**游戏模板**结构特征定位更稳。

### 游戏模板：重启游戏后不用重新分析

Unity 游戏的对象地址**每次启动都会变**（ASLR + GC 压缩），固定地址没有意义，模板存的是**结构特征**（字段类型 + 附近字段验证范围）。

- **内置模板**（Scritchy Scratchy / 挂个爽）：切到「游戏模板」页 → 附加进程 → 选定位目标（金钱/声望）→ 输入当前值 → **自动定位** → 直接改字段。
- **自定义模板**：数值扫描页右键候选地址 → **保存为模板...** → 下次直接在「游戏模板」页下拉里选它，输入当前值重新定位即可。

### 手动读写

「手动读写」页输入任意十六进制地址（如 `0x17A7FA55590`）即可读取/写入，适合高级玩法。

## 后续开发交接

### 架构总览

```
GameModder.py
├── Win32 API 封装层        OpenProcess / Read/WriteProcessMemory / VirtualQueryEx / 图标提取
├── MemoryScanner 引擎       attach / 内存区域枚举 / 精确扫描 / 模板定位 / 读写 / 过滤
├── TEMPLATES + user_templates  内置/用户游戏结构模板（anchor + verify + fields）
└── GameModderGUI           tkinter 界面（数值扫描页 / 游戏模板页 / 手动读写页 / 进程选择框 / 模板保存框）
```

### 核心概念

- **值类型**：`double`(8B) / `float`(4B) / `int64`(8B) / `int32`(4B)，`pack_value` / `unpack_value` 统一处理。
- **扫描**：`scan_exact(value, vtype, full=True)` 全内存精确扫描（对齐过滤 + 全零段跳过）。`full=True` 是**必须的** —— 旧的 `max_hits` 截断模式会在低地址区耗尽配额，永远扫不到托管堆里的小整数（如声望 33），这是本项目踩过的最深的一个坑。`scan_range(vmin, vmax, vtype)` 做区间扫描（输入 `1M~1.01M` 这类区间时自动切换），用于显示值四舍五入、内存实际值不精确的场景。
- **模板定位**：`scan_template(value, vtype, verifies)` 全内存扫 anchor 值，在**已读内存块内**做结构验证（零额外系统调用），不按命中数截断。`verify` 支持 `expect`（等值）/ `min` / `max`（范围）/ 偏移可负。
- **候选过滤**：`filter_equal/changed/unchanged/increased/decreased` 对候选列表逐地址重读比对，多轮收敛。
- **写后读回校验**：`_write_addrs` 写入后立即读回，不一致时自动补写其余候选（≤30 个），这是对 Unity 多副本内存的关键防御。

### 关键工程约束（踩坑总结，改动时务必遵守）

1. **worker 线程绝不访问 tkinter 控件**。后台扫描/定位线程只能做纯计算 + `msg_queue.put()`，任何 UI 输入必须在主线程解析后传参。否则 Tcl 跨线程调用会**死锁挂死**。
2. **消息泵解包格式严格**。`_poll_queue` 用 `kind, payload = get_nowait()` 解包，所有 `put` 必须是 2 元组（如 `("scan_done", (n, action))`）。塞 3 元组会让消息泵崩溃、UI 冻结。
3. **`ttk.Treeview.insert` 不要传 `image=None`**。Python 3.14 tkinter 下参数解析会错乱崩溃，无图标时用条件分支不传该参数。
4. **Unity IL2CPP 地址不稳定**。托管堆对象会因 GC 压缩/重启移动，定位结果短时有效；数值变化或运行久了必须重新定位。这是此类游戏的常态，不是 bug。
5. **`scan_exact` 的 `full=True` 模式**：自动按类型对齐过滤（double/int64 8 字节、float/int32 4 字节），anchor 为 0 时跳过全零段，避免扫 0 卡死。
6. **float 比较必查 nan**。`abs(nan - expect) > tol` 为 False 会让垃圾候选"通过"验证，`_check_verify_block` 已对 nan/inf 直接判失败。
7. **负数 verify 偏移合法**。结构字段（如声望的 totalSpent 在 anchor 之前）可用 `{"offset": -0x28}`，`scan_template` 的零段跳过已按 `vlo/vhi` 处理。

### 新增一个游戏模板（最常用开发任务）

在 `TEMPLATES` 列表追加结构，或让用户在 GUI 右键保存：

```python
{
    "name": "游戏名",
    "process": "Game.exe",
    "locates": [{
        "label": "金币 Money (double)",
        "hint": "游戏界面当前 Money 值",
        "anchor": {"type": "double", "anchor_offset": 0x00, "align": 8,
                   "verify": [
                       {"offset": 0x08, "type": "double", "min": 0.0, "max": 1e7, "desc": "相邻字段"},
                   ]},
        "fields": [
            {"name": "Money 现金", "offset": 0x00, "type": "double"},
        ],
    }],
}
```

分析新游戏结构的推荐流程：先扫出目标值的一个命中地址 → 手动读写页 dump 前后 0x60 字节 → 确认 anchor 字段类型与偏移 → 相邻取 1~3 个稳定字段做 verify（用范围而非等值，因为游戏数值会变）。

### 打包 exe

```bash
pip install pyinstaller
pyinstaller --onefile --windowed --icon=modder.ico \
    --add-data "modder.ico;." \
    --name GameModder GameModder.py
```

产物在 `dist/GameModder.exe`。注意：exe 内置的是 Python 环境，源码改动后需重新打包。若用 `--specpath` 指定构建目录，`--add-data` / `--icon` 需用绝对路径（相对路径会被解析到 spec 目录）。exe 运行时配置文件/用户模板写在 exe 所在目录（`sys.frozen` 路径策略）。
